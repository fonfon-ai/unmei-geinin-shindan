# 製品仕様

## 目的

普段あまりお笑いを見ない人に、「自分では探せなかったが、実際に見たら好きになりそうな
芸人・落語家・番組・動画」を発見してもらう。ユーザーにお笑いの知識を要求せず、誰でも答えられる
生活習慣・性格の質問だけで診断する。エンターテインメント目的の推薦であり、医学的・心理学的診断ではない。

## プロダクト名・コピー

- 名称: **運命のお笑い診断**
- メインコピー: **あなたを笑わせる、運命のお笑いが見つかる。**
- 説明文: 休日の過ごし方や生活習慣、性格についての簡単な質問に答えるだけ。まだ知らない芸人・落語家・番組・動画との出会いを提案します。

## 体験フロー

1. 印象的なトップ画面と「無料で診断する」ボタン、短い説明
2. 17問（うち任意5問）に1問1画面で回答。進捗表示あり
3. 診断中の短い演出（`prefers-reduced-motion` に対応）
4. 性格タイプ（全12種）の判定
5. 結果表示: 運命のお笑い / 初心者向け / おすすめ番組 / 最初に見る公式動画 / 意外な推薦 / 別世代 / 落語の入口
6. 再診断・SNS共有

登録不要・約2分。1問3〜5択。任意項目や「わからない/回答しない」を適切に用意。

## 技術要件（達成状況）

- GitHub Pages で動作する完全静的サイト（DB・サーバ・外部LLM・外部APIなし）— 達成
- APIキー/Firebase/Supabase 等を使わない — 達成
- 回答を外部送信せず、localStorage/Cookie/解析にも保存しない — 達成
- 診断はブラウザ内で完結、オフラインでも診断・結果表示が可能 — 達成
- 質問・推薦候補・採点ルールを TypeScript/JSON で管理 — 達成
- React + TypeScript + Vite、スマホ優先レスポンシブ — 達成
- プロジェクトページ配下（`/unmei-geinin-shindan/`）でパスが壊れない base 設定 — 達成
- 最新安定版・必要最小限の依存、本番で source map 非公開 — 達成

## 結果画面に含む要素

- 診断タイプ名・キャッチコピー・人物像・笑いとの相性
- あなたの運命のお笑い（本命2〜3組）
- 初心者向け（1〜2組）
- おすすめ番組（1〜3本）
- 最初に見る公式動画（2〜4本）＋「まずは○分だけ」提案
- 意外な推薦（1組）・別世代（1組）・落語の入口（1名＋演目）
- 各候補の相性表示と、控えめなトーンの理由
- 再診断・SNS共有

## トーンと表現

- 断定しすぎない（「〜を好む可能性があります」「まずはこちらから」「意外に相性がよいかもしれません」）。
- 「科学的に証明」「正確性99%」「必ず当たる」等は使わない。
- 年齢・性別・飲酒・喫煙を推薦理由として直接表示しない。

## アクセシビリティ

- WCAG AA 相当のコントラストを目安。色だけで状態を伝えない（選択にはチェック記号も併用）。
- キーボード操作可能、フォーカス表示を残す、`aria` 属性を付与、`prefers-reduced-motion` 対応。
- 質問はセマンティックな `radiogroup`/`radio` で提供し、スクリーンリーダーで理解可能。
- Web フォントに依存せずシステムフォント中心、文字サイズを固定しすぎない。

## デザイン方針

業務システム風にしない。明るく少し不思議で試したくなる、柔らかいニュートラル＋アクセントカラー。
特定の性別を前提としない。写真・ロゴを使わず、独自の図形・配色・CSS装飾で魅力を出す。
