# 診断ロジックの詳細

本アプリの診断は、**実行時にLLMやAPIを一切使わない、決定論的な採点・推薦ロジック**だけで動作します。
同じ回答は必ず同じ主結果（診断タイプ・本命芸人）を返します。ランダム診断ではありません。

パイプライン:

```
回答 → 潜在特性ベクトル → 笑いの嗜好ベクトル → 診断タイプ判定
                                          ↘ 候補ランキング → 多様性制御 → 推薦
```

関連コード: `src/data/questions.ts`, `src/engine/traits.ts`, `src/engine/humor.ts`,
`src/data/diagnosisTypes.ts`, `src/engine/recommend.ts`, `src/engine/index.ts`。

## 1. 質問から潜在特性への変換

生活習慣・性格に関する17問（うち5問は任意）に回答します。お笑いの好みは直接聞きません。

各選択肢は、複数の**潜在特性（トレイト）軸**への重み `weights` を持ちます。1つの選択肢は
原則2〜3軸に分散して寄与し、1問・1回答が結果を過度に左右しないようにしています。

トレイト軸（12種、`src/types.ts` の `TraitAxis`）:

| 軸 | 低 (−) | 高 (+) |
|---|---|---|
| extroversion | 内向 | 外向 |
| planning | 即興 | 計画 |
| stimulation | 安定志向 | 刺激志向 |
| analytical | 共感志向 | 分析志向 |
| sociability | 少人数好み | 社交的 |
| novelty | 保守 | 新奇性志向 |
| tensionTolerance | 気まずさ苦手 | 緊張耐性 |
| verbalInterest | 低 | 言葉・構造への関心 |
| relationshipInterest | 低 | 人間関係への関心 |
| tempoPreference | ゆっくり | 速い |
| attentionSpan | 短い | じっくり |
| physicalVisual | 低 | 視覚・身体表現への親和 |

### 重み付けと正規化

`computeTraits(answers)` は、回答された選択肢の重みを軸ごとに合計し、
**軸ごとの正規化係数**（＝全質問における「その軸に最も強く効く選択肢の絶対重みの合計」）で割って、
概ね `[-1, 1]` に収めます（範囲外は clamp）。未回答・中立選択肢は寄与ゼロです。

このため、**全問スキップでも全軸ゼロ（中立）として有効に処理され**、エラーになりません。

### 単一回答が結果を支配しないことの担保

- 正規化係数により、単一の回答が1軸に与える影響には上限があります（テストで `maxSingleAnswerInfluence() ≤ 0.6` を検証）。
- 診断タイプは9軸の嗜好ベクトル全体で決まるため、1つの軸だけでは決まりません。
- 「ランダムなベースライン回答から1問だけ差し替えたとき、タイプが変わる割合は半数未満」であることをテストで検証しています（独裁的な質問がない）。

## 2. 潜在特性から笑いの特徴への変換

`traitToHumorPreference(traits)` が、12のトレイトを**9つの笑いの特徴軸**の嗜好（各 `0..1`）へ線形写像します。
係数行列は `src/engine/humor.ts` の `TRAIT_TO_HUMOR`。

笑いの特徴軸（`HumorAxis`）:

| 軸 | 意味 |
|---|---|
| incongruity | 不一致・意外性 |
| safety | 安心感・安全性 |
| edge | 毒・いじり・優位性 |
| tensionRelease | 緊張と解放 |
| relational | 協調性・関係性 |
| physical | 身体性・リアクション・視覚 |
| verbal | 言葉中心・構造・知的 |
| tempo | テンポ（速さ） |
| worldview | 世界観・シュール・ナンセンス |

例）「刺激志向・新奇性が高い」→ incongruity/edge が上がる。「疲れていて安定志向」→ safety が上がる、など。
単純なステレオタイプ（例：喫煙→毒舌、女性→恋愛ネタ）で直接芸人へ結びつけることはしていません。
複数回答を統合した潜在傾向からのみ、笑いの特徴を推定します。

## 3. 診断タイプの判定

診断タイプは12種（`DIAGNOSIS_TYPES`）。各タイプは9軸空間上の**中心ベクトル（centroid）**を持ちます。
`classifyType()` は、ユーザーの嗜好ベクトル（強い軸を強調したもの）と各中心とのコサイン類似度を計算し、
最も近いタイプを選びます。同点は id 昇順で安定化します。

- 全12タイプがランダム回答から到達可能であることを自動テストで検証（未到達タイプゼロ）。
- 各タイプの中心ベクトルは、それ自身に分類されること（識別可能性）もテスト済み。

## 4. 推薦スコアと候補ランキング

各候補（芸人・落語家）は、スタイルタグとフォーマットから**同じ9軸のベクトル**を導出して持ちます
（`deriveHumor()`）。ユーザー嗜好ベクトルとのコサイン類似度でランキングし、同点は id で安定化します。
表示用の「相性%」は類似度を 40〜99 にマッピングした値です。

番組も同様に9軸ベクトルを持ち、fit・初心者やすさ・配信状況で並べ替えます。

## 5. 多様性制御

上位候補から、単調にならないよう役割ごとにバランスよく選びます（`recommend()`）。

- **本命の運命の芸人**：総合上位（2〜3組。2組目以降は世代の多様性を軽く優先）。
- **初心者向け**：`beginnerAccessibility` の高い候補。
- **意外な推薦**：中位で、ユーザーの第1嗜好軸とは主軸が異なる候補。
- **別世代**：本命と異なる世代グループ（昭和/平成/令和）の最上位。
- **落語**：落語カテゴリの最上位（初心者向け演目つき）。

各枠のエンティティが重複しないこと、落語枠が落語であること、別世代枠が本命と別世代であることをテストで検証しています。

## 6. 年齢・性別・飲酒・喫煙・MBTI の扱い

- **年齢・性別**：任意項目。**採点への重みはゼロ**。結果や推薦理由に直接反映しません（統計・将来の改善余地のために選択肢だけ用意）。
- **飲酒・喫煙**：任意項目。良し悪しを評価しません。未成年に配慮し「しない」「年齢上該当しない」「回答しない」を用意。重みは非常に小さく、単独では結果を左右しません。
- **MBTI**：任意項目。**多くの入力のうちの弱いヒント**として、外向/内向・新奇性・計画性へ小さく寄与するだけで、MBTIだけで結果は決まりません。「知らない/回答しない」も用意。
- これらを**推薦理由の文章に直接表示しません**。推薦理由は、複数回答から得られた笑いの傾向を自然文に変換して生成します。

## 7. 実行時にLLM・APIを使っていないこと

診断・推薦・結果説明はすべて、事前に定義した重み・写像・カタログ・テンプレートで計算されます。
ネットワーク接続がなくても、診断と結果表示は動作します（外部リンクを開くときのみ通信）。
LLMは開発時に、質問設計・写像設計・タグ付け・タイプ設計・推薦理由テンプレートの検討にのみ用い、
最終成果物は決定論的ロジックだけで動きます。

## 8. これは科学的な心理診断ではありません

本ロジックは学術的な性格・心理検査に基づくものではなく、エンターテインメント目的の推薦です。
「科学的に証明」「正確性99%」「必ず当たる」といった表現は用いません。結果は「〜かもしれません」という
控えめなトーンで提示します。

## 9. 将来の改善時の注意点

- 重みや写像を変えると、タイプの到達可能性・多様性・単一回答支配度が変わります。変更後は必ず
  `src/engine/engine.test.ts` を実行し、**全タイプ到達可能・決定論・単一回答が支配しない**ことを再確認してください。
- カタログに候補を追加する際は、`src/data/catalog.test.ts` の検証（重複ID・URL許可・世代網羅・事務所の偏り）を満たすこと。
- 単純なステレオタイプ（属性→芸人の直結）を新たに導入しないこと。
- 推薦理由・結果文に、年齢・性別・飲酒・喫煙・MBTI を直接出さないこと。
